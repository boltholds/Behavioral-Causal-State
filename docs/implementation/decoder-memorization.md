# Диагностика запоминания декодера

Проверяется узкий вопрос: может ли текущий SONAR reader + event decoder точно восстановить небольшой **обучающий** набор при увеличении числа обновлений. Это проверка оптимизации и использования входа. Ни запоминание, ни его отсутствие в ограниченном бюджете не устанавливают достаточность SONAR для новых историй.

Предыдущие concat/attention/GRU runs выполнили всего 30/46/60 optimizer steps. Выбранные по validation checkpoints соответствуют 20/36/54 шагам: они сохранены до конца этих runs. На восьми выбранных train histories все три старых checkpoints дают full-history error 1.0; даже при правильном префиксе token error составляет 0.329918 /0.338115 /0.346311. Teacher NLL: 0.915078 /0.765499 /0.808169. Пошаговый и пакетный вывод с одинаковым правильным префиксом имеют 0 argmax disagreements; максимальное расхождение допустимого logit≤6.68e-6. Это проверяет совпадение двух вычислительных путей, но не качество свободной генерации.

## Зафиксированный протокол

[decoder-memorization-v0.1.json](../../experiments/protocols/decoder-memorization-v0.1.json) создан до новых прогонов. Вход — ранее проверенный SONAR cache и train labels из 128-history diagnostic subset. Registered L1 protocol, encoder, causal core и src/bcs в этом этапе не меняются.

- `single`: первая train history длины 4.
- `eight`: первые две истории с различными полными targets каждой длины 4/8/12/16. Отбор следует порядку файла и не учитывает ошибки старых моделей.
- Для каждой стадии и каждого reader создаются новые веса и optimizer, seed 11. Всего 6 runs.
- AdamW, lr 0.0003, weight decay 0.01, dropout 0.1, clip norm 1.0. Full batch выбранного набора; CPU, 4 threads. Максимум 1000 optimizer steps.
- Оценка на step 0 и каждые 25 шагов. `memorized` требует три последовательные проверки после обновлений с полным совпадением каждой greedy history, включая EOS, и 0 invalid decodings. Иначе после 1000 шагов — `budget_exhausted`.

В этом протоколе train и evaluation intentionally совпадают. Нет validation early stopping, подбора learning rate, усечения длин или нормализации embeddings. Результаты нельзя включать в таблицу generalization/L1 как test accuracy.

## Измерения и controls

Teacher-forced NLL, token/history errors и ошибки по полям описывают предсказание при **истинном** префиксе. Free-running metrics считаются отдельным вызовом `greedy(z, lengths)`; этот вызов не получает targets. Для него сохраняются full-event/history errors, invalid decodings, termination errors и поле первого расхождения.

После обучения оцениваются:

1. Исходные embeddings.
2. Нулевые embeddings при прежних длинах и масках.
3. Для eight — обмен двух входов внутри каждой группы одинаковой длины. Каждый вход меняется, длины остаются прежними, правильные histories различаются. Результат сравнивается и с исходным recipient target, и с target донора входа.

Если исходные и donor-aligned переставленные inputs восстанавливаются 8/8, а recipient-aligned перестановка даёт 0/8, модель использует различия между embeddings. Это совместимо с обычным запоминанием record-specific признаков; понимание причинных операций или перенос отсюда не следуют. Для single permutation неприменима, а запоминание одной истории возможно вообще без использования текста.

## Запуск и provenance

Из корня checkout, после подготовки артефактов [предыдущего этапа](language-runtime.md):

```sh
python -m experiments.diagnostics.decoder_memorization \
  --dataset artifacts/language-diagnostic-v0.1 \
  --cache-root artifacts/language-diagnostic-v0.1/embeddings \
  --baseline-runs artifacts/language-diagnostic-v0.1/runs \
  --output artifacts/decoder-memorization-v0.1
```

Output должен быть пуст. Runner проверяет исходный input lock до и после работы, сохраняет hashes нового протокола, своего исходника и точного отбора записей. Старые checkpoints проверяются существующим restore API. Новые checkpoints имеют отдельные schema/scope и остаются train-set diagnostics. Перед завершением каждого run веса загружаются обратно, свободные predictions сверяются. При каждом restore дополнительно проверяются текущие hashes всех src/bcs файлов, diagnostic runner и протокола. Неподдерживаемые декларации протокола (длины, отбор, controls, device) отвергаются, чтобы они не расходились с фактическим выполнением. Compact reports публикуются в git; model.pt и исходные vector matrices остаются генерируемыми артефактами.

Полный L1, геометрическая диагностика и TTT в этот эксперимент не входят. Качество на новых историях потребует отдельного обучения и закрытого test protocol; текущий опыт не меняет его gates.

## Фактический результат: 2026-10-04

Все 6 runs завершены со статусом `memorized`. Числа ниже относятся к исходным **обучающим** историям. Первый точный checkpoint и подтверждение трёх последовательных точных проверок указаны раздельно.

| Reader | Single: первый точный / подтверждённый step | Eight: первый точный / подтверждённый step | Eight: точных histories | Eight: teacher NLL | Eight: время, s |
|---|---:|---:|---:|---:|---:|
| concat | 75 /125 | 225 /275 | 8/8 | 0.034430 | 63.81 |
| attention | 50 /100 | 300 /400 | 8/8 | 0.001200 | 130.62 |
| GRU | 50 /100 | 225 /275 | 8/8 | 0.030223 | 63.20 |

На финальных checkpoints всех6 runs: teacher token error 0, free-running full-history error 0, invalid decodings 0. Для attention первое 8/8 не стало немедленным завершением: критерий последовательных успешных проверок подтвердился только на 400-м шаге. Поэтому отчёт не выбирает один удачный checkpoint.

| Reader, eight | Исходные inputs: точных histories | Нулевые embeddings | Перестановка: совпадения с прежним target | Перестановка: совпадения с target нового входа |
|---|---:|---:|---:|---:|
| concat | 8/8 | 1/8 | 0/8 | 8/8 |
| attention | 8/8 | 3/8 | 0/8 | 8/8 |
| GRU | 8/8 | 1/8 | 0/8 | 8/8 |

При сохранении длин и масок подмена embeddings меняет ответы. Это подтверждает использование различий входа на выбранных восьми запомненных историях. Нулевой control относится к входам вне обученного распределения; его ошибка сама по себе не измеряет причинную или семантическую компетентность. На single attention сохраняет правильный ответ даже при нулевом входе, что ожидаемо допустимо при запоминании одного target.

**Вывод:** неизменённые reader+decoder способны точно запоминать этот небольшой набор реальных SONAR embeddings. Предыдущий отрицательный результат 128/32 не доказывает неспособность архитектуры обучаться. Этот опыт не выделяет единственную причину того результата: одновременно изменены размер обучающего набора, число обновлений, batch size и правило остановки. Обобщение на новые истории, достаточность SONAR и сравнительное превосходство агрегаторов остаются непроверенными. Ни один результат не засчитан как прохождение L1.

Следующий содержательный шаг — обучение на большем train-наборе с отдельной validation, кривыми качества и явным бюджетом optimizer steps. Для зарегистрированного L1 по-прежнему нужны human review каталога, предусмотренный tuning, пять seeds и закрытые test gates.

Сохранены [сводный отчёт](../../experiments/results/decoder-memorization-v0.1/summary.json), [краткие результаты и проверка](../../experiments/results/decoder-memorization-v0.1/verification.json), [точный отбор](../../experiments/results/decoder-memorization-v0.1/selection.json), [метрики прежних checkpoints](../../experiments/results/decoder-memorization-v0.1/baseline.json), все curves, controls, targets/predictions и checkpoint metadata. Суммарное время шести fits — 279.51 s; это измерения CPU, а не сравнение при фиксированной аппаратной нагрузке.

Проверки кода: **179 tests passed in 21.14s**. Независимое ревью выявило пробел в проверке текущей реализации при restore; исправлены hashes runtime/runner/protocol. Замечание об игнорируемых декларациях протокола повышено до обязательного исправления, поскольку меняет смысл эксперимента. Все 9 новых regression cases сначала воспроизвели ошибки, затем прошли. Исходный input lock повторно проверен после runs; все 6 checkpoints восстановлены, predictions совпали.

Решения и границы ревью: работа ведётся прямо в main по разрешению пользователя; runner расположен вне src/bcs и отдельно хешируется, поэтому команда требует checkout. Фиксированный бюджет 1000 не расширялся после просмотра результатов. Неподдерживаемое изменение дизайна требует новой версии runner/protocol. Проверка teacher/step использует общие grammar masks и проверяет вычисление logits, а не независимую корректность grammar; её покрывают отдельные существующие тесты. Эмпирические выводы сделаны по фактическим runs после ревью. Отложенных замечаний этого ревью нет; ограничения прошлого этапа остаются перечисленными в его отчёте.
