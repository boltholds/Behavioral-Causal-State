# SPEC-03 — Языковой pipeline

Статус реализации: SONAR adapter, три reader branches, авторегрессионный decoder и diagnostic trainer реализованы; полный L1 study runner ещё не завершён. [Фактические команды, результаты и ограничения](../implementation/language-runtime.md). Протокол и числовые gates ниже сохранены.

## Вход и условная достаточность

T₁:ₜ — последовательность сообщений. zᵢ=enc_θ(Tᵢ) — per-utterance embedding. SONAR/LaBSE не назначаются энкодерами всей истории. Grounder читает Z₁:ₜ непосредственно либо representation agg_φ(Z₁:ₜ). Метаданные границ сообщений, их порядок и роль источника известны всем веткам одинаково. Семантические поля Γ не подаются через metadata.

Causal head получает Γ или распределение интерпретаций после grounding. В v0.1 downstream benchmark использует greedy decoded Γ и общий frozen core; условные вероятности полей оцениваются отдельно. Маргинализация по интерпретациям — следующий вариант, с учётом оставшейся массы и без заявления, что beam является полным posterior.

В первом L1 обязательны два измерения: структурное декодирование и причинные ответы. Геометрическая диагностика GEO-1 отложена и не является обещанным результатом первого запуска; её проект ниже и статус в [deferred.md](deferred.md). Близость эмбеддингов сама по себе не доказывает потерю различия. Exact injectivity также не гарантирует практическую обучаемость readout.

## Четыре ветки L1

| Ветка | Интерфейс истории | Начальный readout |
|---|---|---|
| oracle | Истинная Γ доступного журнала | Тот же обученный core |
| concat | 16 слотов исходных z, padding mask, длина, порядок | Flatten → MLP 256→256 (GELU); контекст к event decoder |
| attention | Все z с позиционными признаками | Projection 256; 2 Transformer encoder блока, 8 heads, FFN 1024; event decoder с cross-attention к всем позициям |
| gru | Только последний hidden state | Однослойный GRU, hidden=256; контекст к event decoder |

Общий event decoder: однослойный GRU hidden=256, teacher forcing при обучении; авторегрессионный greedy вывод при оценке. В concat/GRU контекст доступен на каждом шаге; в attention доступен повторный cross-attention. Все ветки используют одинаковый словарь структурных полей, valid-type masks и EOS. Masks не подсказывают правильное значение. Не требуется одинаковое число параметров: оно, FLOPs и пиковая память публикуются; бюджет подбора одинаковый.

Замороженные исходные embeddings сохраняются в float32 без дополнительной нормализации/квантизации в основном сравнении. Checkpoint, tokenizer и их хеши фиксируются в run manifest. Никакого raw-text bypass, прежней истинной Γ или кэша decoded histories в embedding-only ветках.

Concat до первого learned слоя обратим относительно Z при известной маске. MLP после concat способен терять информацию. Attention хранит последовательность t×d, а не обязательно один вектор d. GRU в этой ветке экспортирует только последний hidden state. Монотонный порядок ошибок concat→attention→GRU не предполагается.

**Назначение concat — самостоятельный baseline плотного чтения фиксированного окна.** У него нет recurrent или attention структуры до MLP, и ему доступны все исходные sentence embeddings. Он проверяет, достаточно ли такого простого readout при заданном бюджете. Его отличие от остальных веток включает inductive bias, число параметров и оптимизацию; оно не измеряет чистую информационную потерю history aggregation.

Concat не является верхней/нижней границей качества. Attention может оказаться лучше. Comparator для noninferiority выбран заранее как инженерная точка сравнения и используется вместе с абсолютным gate относительно oracle. Положительный результат любой SONAR-ветки показывает извлекаемость в заданном стенде; провал concat не отменяет успех другой ветки. Нужность более сложного reader обсуждается по качеству и стоимости, без требования монотонного порядка.

Для фиксированных детерминированных reader и неограниченного decoder при log-loss:

R*(W)=inf_g E[-log g(Γ*|W)].

R*(T)≤R*(Z)=R*(concat(Z)); R*(Z)≤R*(attention_rep(Z)); R*(Z)≤R*(gru_rep(Z)). Между двумя последними значениями общего порядка нет. Разности ошибок обученных моделей не равны разностям неизвестных Bayes risks.

## Факторизация grounder

Γᵢ=(τᵢ,κᵢ,eᵢ,rᵢ,νᵢ,vᵢ). Используется цепное разложение:

$$P(\Gamma_{1:t}\mid W)=\prod_i\prod_j P(\gamma_{ij}\mid W,\Gamma_{<i},\gamma_{i,<j}).$$

Здесь Γ предыдущих событий и уже выведенные поля текущего события входят в conditioning; порядок полей: time, mode, entity, predicate, negation, value. Это chain rule, а не предположение независимых голов. Shared decoder и отдельные conditional output heads допустимы.

Основные метрики снимаются free-running. Teacher-forced метрики по истинным префиксам публикуются дополнительно для локализации распространения ошибок.

Для каждого поля: exact match и confusion matrix; для negation дополнительно scope; для сущностей binding accuracy; для времени event-reference accuracy; для value отдельно false/unknown. Публикуются full-event и full-history exact match, недопустимые комбинации и downstream TV.

## Отложено: геометрический диагностический отчёт GEO-1

Статус: deferred; в L1 report поле geometry_diagnostic="deferred", а не нулевой score. Проект диагностики сохраняется для следующего протокола. Для Z планируется RMS расстояние по выровненным padded слотам; нормализация каждой координаты использует только train mean/std с floor 10⁻⁶. Длина и маска включаются в описание пары. Нормализация для диагностики не меняет вход основного learner. Метрики hidden-state геометрии GRU/attention также отложены.

Формальное d_Q определено в [SPEC-01](01-causal-state.md). Будущая конечная диагностика на фиксированных C_eval,Q_eval и парах из [генератора minimal pairs](04-generator.md):

$$\widehat d_Q(h,h')=\max_{M\in C_{eval}}\max_{q\in Q_{eval}}TV(R_M(h,q),R_M(h',q)).$$

δ̂(L)=max_pairs [d̂_Q(h,h′)−L·d_Z(Z(h),Z(h′))]₊.

Сетка L={0,0.1,1,10,100}, δ∈[0,1]. L здесь — заранее выбранная ось sensitivity curve, не оценка «истинной Lipschitz-константы». Будет публиковаться вся кривая, без выбора удобной точки на test. До запуска GEO-1 MUST перечислить конкретные модели, запросы, pair IDs, общий admissible domain и обработку разных длин в отдельном manifest. Пока это не сделано, геометрия не считается операционализированным experiment track. Глобальная Lipschitz-гарантия не заявляется.

## Следующие controls

LaBSE и SONAR pre-pooling token states добавляются после L1 отдельными версиями. Token-level контроль убирает sentence pooling, но сам по себе не проверяет потерю в history aggregation. Для каждой такой ветки фиксируется собственный history reader.

Mean pooling без позиции — допустимый отрицательный контроль перестановок, не основной baseline. Длины 24/32 проверяются только архитектурами, допускающими такой вход; concat-16 не оценивается через скрытое усечение.
