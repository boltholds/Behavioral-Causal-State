# SPEC-04 — Генератор трасс, текстов и пар

**Статус: генератор специфицирован, но ещё не реализован.** Этот документ задаёт входы, алгоритм и требуемые артефакты; он не является свидетельством прохождения G1. G1 можно выполнить только на реально сгенерированном наборе. [Критерии G0/G1/G2](05-evaluation.md) и [граница первого запуска](deferred.md).

## Слои и разделение доступа

WorldSpec + indexed U → PhysicalTrace → VisibleJournal Γ* → RenderedHistory T. Learner получает T, структурированные train labels Γ*, зарегистрированные режимы сбора данных и schema. Evaluator отдельно получает WorldSpec и U. В test labels и U learner недоступны.

Oracle grounding использует только VisibleJournal, включая маркеры unknown для явно сообщённого отсутствия измерения. Истинные скрытые/неизмеренные значения в oracle Γ не попадают. Гипотетическая реплика не является фактически выполненной интервенцией. Renderer гарантирует достоверность фактических утверждений; ошибки/ложь источника вне v0.1.

## Физический мир

Две независимые копии устройства. У каждой R — latch, M — relay, C — load, Y — output; все бинарные. Команда A∈{start,stop,hold}. Для одного шага:

$$C_{k+1}=C_k,$$
$$R_{k+1}=\begin{cases}1&A_k=start\\0&A_k=stop\\R_k&A_k=hold,\end{cases}$$
$$M_{k+1}=R_{k+1}\oplus N^M_{k+1},$$
$$Y_{k+1}=(M_{k+1}\land\neg C_{k+1})\oplus N^Y_{k+1}.$$

Порядок вычисления C,R → M → Y. Hard clamp заменяет уравнение соответствующего узла в указанном срезе. Последствия сохраняются обычной динамикой: clamp C меняет C следующих шагов через copy, clamp R сохраняется при hold, clamp M не имеет собственного ребра памяти.

Reset: R₀=0; C₀~Bernoulli(0.5) независимо между устройствами. M₀,Y₀ вычисляются по тем же уравнениям с U₀. Reset создаёт новый эпизод и новый U; это не восстановление контрфактуального контекста.

Clock общий для двух устройств. Выполненная команда одному устройству продвигает clock на 1; второму выполняется hold. Интервенционное событие также продвигает clock, обычные действия обоих устройств при этом hold. Чтение состояния, отрицание выполнения команды и гипотетическая реплика clock не продвигают.

## Режимы

| ID | Шумы | Доступные естественные наблюдения | Назначение |
|---|---|---|---|
| deterministic | Nᴹ=Nʸ=0 | R,M,C,Y | Первый L1 и T0 |
| stochastic_full | Независимые Bernoulli(0.1) | R,M,C,Y | Положительные do/CF проверки |
| stochastic_partial | Та же физика | R,C,Y | Отделить partial observation от стохастики |
| correlated_partial | Nᴹ=Nʸ=B, B~Bernoulli(0.1) | R,C,Y | Нарушение независимости |
| wrong_gate_partial | Независимые Bernoulli(0.1); Y=(M∧C)⊕Nʸ | R,C,Y | Нарушение формы механизма |

Векторы шумов iid между временем и устройствами; shared noise означает только зависимость M/Y одного устройства в одном срезе. Возможность физически выполнить do(M=m) сохраняется в partial: установленное значение известно как действие, естественное M скрыто.

Для положительного стохастического CF вывода класс задаёт Boolean f_j с additive XOR noise, p_j<0.5, независимость между механизмами/временем/объектами и инвариантность к интервенциям. Эти assumptions входят в каждый ответ. Таблицы P(child|parents) без структурной шумовой семантики CF не определяют.

## Генерация базовой языковой истории

1. Выбрать длину L равномерно из {4,8,12,16}, режим и независимые seeds физики/renderer.
2. Два первых сообщения сообщают C₀ двух устройств. Entity ID — порядок первого упоминания; surface names не являются фиксированными метками физических значений.
3. Выбрать одну из оставшихся L−2 позиций равномерно для обязательной выполненной start/stop. Это гарантирует допустимый past-action CF для каждого экземпляра μ_lang.
4. Для остальных позиций: executed command 0.30, single-target clamp 0.20, observation/report-unknown 0.30, hypothetical command 0.10, denied execution 0.10. Объект выбирается равномерно.
5. Для обычной команды P(start|C=1)=0.8, P(start|C=0)=0.2; иначе stop. Это фиксированная logging policy, не интервенционный вывод через conditioning.
6. Для clamp: цель равномерно R,M,C; значение Bernoulli(0.5). Для observation: переменная равномерно из видимых; с вероятностью 0.1 сообщается unknown, иначе истинное значение выбранного текущего среза. Для hypothetical/denied: start/stop равновероятны, factual trace не меняется.
7. Renderer выбирает допустимый шаблон и поверхностные имена независимо от физических значений. В baseline сообщения хронологичны; временные перестановки создаются отдельным challenge transform.

История остаётся разреженным отчётом: все переменные могут быть доступны физически, но не обязательно сообщены после каждого шага. Полный snapshot последнего состояния не добавляется автоматически. Статистики зависимости ответа от прошлых сообщений публикуются, чтобы измерение памяти не стало тривиальным.

Полные физические train-трассы не подаются core в L1. Core обучается по oracle VisibleJournal на тех же train episodes. Для детерминированных таблиц можно дополнительно использовать заранее зарегистрированный fixed calibration panel: все значения родителей R,A; все R для M; все M,C для Y, с выполненными single clamps и наблюдаемыми выходами. Панель одинакова для всех веток, не содержит joint test interventions. Она фиксирует поддержку и её объём учитывается отдельно от 20 000 языковых историй.

Calibration panel deterministic: 6 проверок перехода R (2 значения R×3 команды), 2 проверки M (2 значения R), 4 проверки Y (2×2 значения M,C); всего 12 probes. Подготовительные single clamps на предыдущих шагах учитываются в action budget. Граф известен; truth tables функций скрыты learner. Ни текстовая ветка, ни oracle не получают скрытые метки test.

## Семантический event contract

Каждое сообщение содержит один атомарный event/assertion. Поля Γ: time reference, mode, entity binding, predicate, negation scope, typed value. Неизвестное значение отличается от false. «Stop не выполнялась» обозначает отрицание выполнения, а не команду start.

Примеры seed-шаблонов (surface families для train/test различаются):

| Kind | Шаблон | Семантика |
|---|---|---|
| observed | «У устройства {name} значение {var} равно {value}.» | Факт в текущем срезе |
| action | «На устройстве {name} выполнили команду {action}.» | Переход на следующий clock |
| hard_do | «На следующем шаге принудительно установили {var} устройства {name} в {value}.» | Replacement в следующем срезе |
| hypothetical | «Рассмотрели вариант выполнения {action} на устройстве {name}.» | Не меняет factual world |
| denied | «Команду {action} на устройстве {name} не выполняли.» | Отрицание события |
| unknown | «Значение {var} устройства {name} не сообщалось.» | Unknown report |
| past_observed | «На шаге {time} у устройства {name} было {var}={value}.» | Факт о прошлом срезе |

Явные ссылки на прошлый шаг renderer использует только при наличии соответствующего измерения в журнале. Кореференция, свободные местоимения, многоатомарные предложения и недостоверные сообщения отложены. Начальные templates должны быть грамматически проверены человеком до lock; это не статистическое подтверждение их представительности для естественного русского языка.

## Minimal pairs

Пары создаются преобразованием semantic event plan с последующим повторным исполнением simulator и рендерингом. Нельзя менять текстовый факт и оставлять противоречащие ему последующие измерения. Для order pairs используем планы без зависящих от перестановки factual measurements; иначе пара маркируется semantic contrast, а не lexical minimal pair.

| Категория | Изменение | Ожидание |
|---|---|---|
| paraphrase | Только renderer, Γ* неизменна | Ответы и статусы совпадают |
| negation | Executed stop ↔ denied stop | Меняется факт выполнения |
| mode | Executed stop ↔ hypothetical stop | Только первая меняет world |
| order | start;stop ↔ stop;start без explicit timestamps | Итоговый R/M различается |
| time | Переставить рассказ о событиях при сохранённых timestamps | Физическая хронология и ответы сохраняются |
| binding | Команда A ↔ команда B | Меняется целевой объект |
| knownness | Измерение R=0 ↔ unknown report | Меняется доступное свидетельство |

Для causal-sensitive подмножества evaluator сохраняет q* с TV(R_M*(h,q*),R_M*(h′,q*))≥0.25. Если свидетеля нет, пара остаётся структурным тестом. Для paraphrase/time-invariance требуется равенство ответов, а не различающий свидетель.

Поиск свидетеля детерминированно перебирает Q_eval в порядке: hold, do(C=0), do(C=1), замена прошлой команды; объекты и временные индексы по возрастанию. Приём/отбраковка пары не зависит от ответов обученных моделей. Число отбраковок и итоговое условное распределение публикуются.

## Splits и утечки

20 000 train, 4 000 validation, 4 000 IID test базовых историй. На каждый из 7 challenge types — 2 000 независимых base groups, по два текста в паре. Размер считается по базовым историям/парам, не сообщениям.

Все paraphrases, CF continuations, observation masks и contrast pairs одной исходной группы находятся в одном split. Split назначается до renderer. Структурные дубликаты между split исключаются по evaluator-only semantic key; этот ключ не используется runtime journal.

Challenge families делятся внутри каждого типа поровну на новые template families и новые имена/сочетания известных конструкций (1 000 + 1 000). IID test использует знакомые семейства, новые базовые трассы. Словари, templates, split seed и group IDs входят в manifest. Частоты mode/value/answer по имени, шаблону, длине и пунктуации проверяются на случайные подсказки.

## Контрфактуальный replay

U индексируется как (episode, object, mechanism, physical_time). Перезапуск с тем же обычным RNG seed недостаточен. Замена прошлой start на stop или наоборот сохраняет последующие фактические действия и clamps в исходных срезах; policy не пересэмплируется. Последующие factual measurements используются для abduction, но не принудительно навязываются альтернативному миру. Hypothetical messages в factual evidence не создают наблюдений из другого мира.

Единичный CF-pair с сохранённым U — одна реализация, не полный conditional distribution. Эталон R_M(h,q) получается суммированием по всем U, совместимым с видимым factual evidence; в детерминированном режиме и известном начальном состоянии он вырожден. Будущие шумы интегрируются, а не читаются из тайной траектории evaluator.
